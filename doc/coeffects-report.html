Research Notes — Type Theory & Category Theory

Structural Coeffects and Indexed Comonads

Algebraic structures, context representations, and the flat/structural distinction

Sources: Petricek, Orchard & Mycroft 2013/2014 · Brunel, Gaboardi, Mazza & Zdancewic 2014 · Wood et al. 2022

1. The Flat / Structural Distinction

Coeffect systems track how a term uses its context — not what it produces (that is effects), but what it demands from its environment. Two fundamentally different ways of attaching coeffect information to a typing context have been identified, with distinct algebraic requirements.

Dimension Flat coeffects Structural coeffects
Context form Γ @r ⊢ e : τ x₁:τ₁,…,xₙ:τₙ @⟨r₁,…,rₙ⟩ ⊢ e : τ
Annotation granularity Single r for the whole context Vector ⟨r₁,…,rₙ⟩ — one per variable
Categorical semantics Ordinary (monoidal) comonad on a CCC Indexed comonad — a comonad Cr for each r
Extra comonad ops needed None beyond counit/cobind merge, split, duplicate on Cr
Algebraic identity One: use (identity for ⊛) Same, but applied pointwise across the vector
Precision (dataflow example) x + prev y → r = 1 (over-approximates x) x + prev y → ⟨0, 1⟩ (exact per variable)

The motivating example — checking the body x + prev y in a dataflow language where prev accesses one past value — makes the imprecision of flat coeffects visible: a flat system infers the context needs r = 1 past values, applying that requirement to all variables including x, which in fact only needs its current value. The structural system infers ⟨0, 1⟩ and captures this exactly.[1]

2. Algebraic Structures Required

2.1 Coeffect algebra (shared base)

Both flat and structural systems are parameterized by a coeffect algebra (R, ∧, ⊛, use, ⊕) providing:

Coeffect algebra — operations

⊛ : R × R → R   sequential composition; use is its identity

∧ : R × R → R   parallel merge (both sub-expressions need the same context)

⊕ : R × R → R   split (context is partitioned between two sub-expressions)

Concrete instances:

  • Implicit parameters — ∧ = ⊕ = ⊛ = ∪ (set union); use = ∅
  • Dataflow (past values) — ∧ = min, ⊕ = max, ⊛ = +; use = 0
  • Quantitative / linear — semiring (R, +, ·, 0, 1); + for merge, · for sequence[3]

2.2 Flat system — ordinary comonad

Flat coeffects have a denotational semantics in an ordinary comonad C on a cartesian closed category, extended with a scalar annotation on the comonad type constructor. The annotation propagates through the algebra but attaches to the whole context type as a single value.

2.3 Structural system — indexed comonad

Structural coeffects require an indexed comonad Cr, first identified by Petricek, Orchard & Mycroft as a novel structure more powerful than ordinary monoidal comonads.[1] The index r ∈ R lives in the coeffect algebra; each Cr is a separate functor, related by the cobind operation across different index values.

Definition — Indexed comonad (Petricek, Orchard & Mycroft 2014)

counit : Cuse τ → τ

cobind : (Cr τ₁ → τ₂) → Cr⊛s τ₁ → Cs τ₂

Note how cobind crosses index levels: consuming a Cr⊛s and returning a Cs reflects how sequential composition factors into the index. An ordinary comonad has a single unindexed functor; the indexed form is strictly more expressive.

The structural system also requires three additional operations on the comonad that the flat system does not need, because it must decompose and recompose per-variable vectors at the context level:

Additional structure required for structural coeffects

merge : Cr τ₁ × Cs τ₂ → Cr∧s (τ₁ × τ₂)

split : Cr⊕s (τ₁ × τ₂) → Cr τ₁ × Cs τ₂

duplicate : Cr τ → Cr (τ × τ)

merge/split handle the introduction/elimination of per-variable context pairs. duplicate handles variable sharing (using a variable in two sub-expressions). These map to the ∧ and ⊕ combinators of the algebra.

3. Typing Rules — The Contrast

The divergence between flat and structural is sharpest in the lambda abstraction rule, which must handle what happens to a bound variable's coefficient when it is abstracted away.

Flat lambda abstraction

The bound variable's coeffect s is merged into the whole-context annotation via ∧. Only one algebraic operation is needed:

Γ, x:τ₁ @(r∧s) ⊢ e : τ₂
[λ-flat]
Γ @r ⊢ λx.e : τ₁ →s τ₂

Structural lambda abstraction

The bound variable gets its own slot ⟨s⟩ appended to the context vector via product extension ×⟨s⟩. This is how the vector grows and shrinks:

Γ, x:τ₁ @(r×⟨s⟩) ⊢ e : τ₂
[λ-struct]
Γ @r ⊢ λx.e : τ₁ →s τ₂

The structural rule no longer needs the ∧ in the premise because the bound variable is a separate slot — there is no mixing with the rest of the context annotation. As a result the structural system loses the ∧ in the lambda rule but gains the per-variable vector precision.

Application (flat, dataflow instance)

In the flat dataflow instance, application must take the maximum of past-value requirements across both sub-expressions, accounting for sequential composition inside the function body:

Γ @r ⊢ e₁ : τ₁ →t τ₂ Γ @s ⊢ e₂ : τ₁
[App-flat-df]
Γ @max(r, s+t) ⊢ e₁ e₂ : τ₂

4. Comonad Morphisms — Implicit Structure

Plausible — not directly evidenced in primary source

A comonad morphism Cr → Cs arises when there is a morphism r → s in the coeffect algebra ordering (subsumption: weaker requirements entail stronger). This corresponds to structural subsumption rules in the type system: if a term requires context annotation r and r ≤ s in the preorder on the algebra, then a context satisfying s also satisfies r.

The primary source (Petricek et al.) does not introduce comonad morphisms as a named algebraic structure in the presentation of the type system. The indexed comonad itself already carries the morphism-like behaviour through cobind's index crossing. However, weakening rules implicitly use the preorder on R, and any monotone map f : r → s in that preorder would induce a natural transformation Cf : Cr → Cs preserving the counit and cobind structure — making it a comonad morphism in the indexed sense.

5. Beyond Structural: Non-Structural Coeffects

Structural (per-variable) coeffects are still insufficient when variables alias each other. Wood et al. (2022) identify a third level: non-structural coeffects arise when the way one variable is used affects the coeffect annotation of another variable. This happens in imperative settings with sharing and mutation, where aliasing between heap locations makes per-variable independence unsound.[4]

The hierarchy of expressive power is:

Expressiveness hierarchy

Flat ≤ Structural < Non-structural

Flat systems are a special case of structural (set the vector to a constant). Structural systems decompose into per-variable independent annotations. Non-structural systems require tracking inter-variable dependencies — algebraic structure beyond a simple coeffect vector; the research here is ongoing.

6. Graded Comonads and Semiring Coeffects

Brunel, Gaboardi, Mazza & Zdancewic (ESOP 2014) take the structural/quantitative approach with a semiring (R, +, ·, 0, 1) as the annotation algebra, where:

  • + combines requirements additively (parallel context use)
  • · composes requirements multiplicatively (sequential)
  • 0 = unused; 1 = linear use

Gaboardi et al. (ICFP 2016) lift the distributive law between effects (monads) and coeffects (comonads) to the graded setting, yielding a syntactic theory of how graded monads and graded comonads interact. A graded comonad Dr is indexed by a monoid element r (rather than an arbitrary algebra element), with multiplication in the monoid controlling how indices compose under cobind.[2] This unifies graded comonads with the indexed comonad framework: a graded comonad is an indexed comonad where the index set carries monoid structure and cobind uses monoid multiplication.

7. Verification of Key Claims

Confirmed — 3/3 sources agree

Flat context form: Γ @r ⊢ e : τ — one annotation for the whole context. Structural context form: x₁:τ₁,…,xₙ:τₙ @⟨r₁,…,rₙ⟩ ⊢ e : τ — per-variable vector. The distinction appears across tomasp.net/coeffects, the Cambridge repository record, and ICALP 2013 summary.

Confirmed — primary source (Petricek's own site)

Indexed comonad operations: counit : Cuse τ → τ and cobind : (Cr τ₁ → τ₂) → Cr⊛s τ₁ → Cs τ₂. The additional merge/split/duplicate operations are required only in the structural system for tensorial context decomposition.

Confirmed — 2/2 sources

Structural lambda rule uses vector extension r×⟨s⟩; flat lambda rule uses algebra merge r∧s. The structural rule eliminates the need for ∧ in the premise, gaining per-variable precision.

Confirmed — explicit in Wood et al. 2022 abstract

Non-structural coeffects exist and are not captured by per-variable vectors: "the way a given variable is used can affect the coeffects of other variables" — arising with sharing/aliasing in imperative settings.

Plausible — inferred, not directly stated

Comonad morphisms induced by the preorder on the coeffect algebra correspond to weakening/subsumption rules. The primary sources do not name these as "comonad morphisms" explicitly; they emerge from the monotone structure of the algebra acting on the indexed comonad family.
