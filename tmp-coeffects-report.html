Structural Coeffects:
Per-Variable Resource Tracking

Queries: "coeffects per-variable resource tracking structural" · "linear types coeffects structural per-variable"
Covers: Petricek–Orchard–Mycroft 2013/2014, Brunel–Gaboardi–Mazza–Zdancewic 2014, Gaboardi et al. 2016, McBride 2016, QTT, Granule

A Concrete Examples of Structural Coeffect Systems

A structural coeffect system annotates each variable in the typing context with its own usage descriptor, drawn from a semiring (or similar algebraic structure). The following are the canonical instantiations, all confirmed in the literature.

Linear Types Structural

Each variable is annotated with a multiplicity from the semiring {0, 1, ω} where 0 = erased/irrelevant, 1 = used exactly once, ω = unrestricted. The context grammar changes: instead of bare x : A one writes x :₁ A (linear) or x :ω A (unrestricted). This is the simplest non-trivial structural instance.

Semiring: ({0, 1, ω}, +, ·, 0, 1) where 1 + 1 = ω, ω + r = ω, 0 · r = 0, 1 · 1 = 1, ω · r = ω (r ≠ 0) Context: x :₁ A, y :ω B ⊢ e : C ^^^^^^^ ^^^^^^^ linear unrestricted -- x must be used exactly once; y may be used any number of times

This is explicitly described as a structural coeffect instance in Petricek–Orchard–Mycroft (ICFP 2014), and in the graded-base calculi of Brunel et al. (ESOP 2014) and Atkey's QTT (LICS 2018).

Graded/Bounded Linear Types Structural

Generalization: the multiplicity is an element of an arbitrary semiring R. For natural numbers, x :ₙ A means "x is used exactly n times." Used in Bounded Linear Logic (Girard–Scedrov–Scott 1992) and central to the Granule language.

Granule example — coeffect polymorphism: twice : (a [c] -> b) [2] -> a [2*c] -> (b, b) ^^^^^^^^^^^^^^^^^^ ^^^^ function used twice argument grade: 2 × c (semiring mult) dup : forall {a : Type} . a [2] -> (a, a) -- parameter type a has grade 2 (used twice)

The Granule language (Orchard et al., ICFP 2019) is the primary working implementation. Functions are linear by default; grades appear explicitly in square brackets. Semiring operations appear directly in grade expressions.

Sensitivity / Privacy Analysis (Fuzz / DFuzz) Structural

Each input variable carries a sensitivity coefficient (a non-negative real or ∞). f : (x :_{2.0} ℝ) → ℝ means the output is at most 2.0 × (change in x). The semiring is (ℝ≥₀ ∪ {∞}, max, +, 0, 1). Used in Reed–Pierce Fuzz (POPL 2010) and Gaboardi et al. DFuzz. This is a structural coeffect system tracking differential privacy sensitivity per-variable.

Dataflow / Caching Analysis Structural

Track how many past time steps each variable needs. Context: x :_{3} A, y :_{1} B ⊢ e : C means the computation needs the last 3 values of x but only the current value of y. Petricek–Orchard–Mycroft (ICALP 2013) use this as a running example to contrast structural vs flat systems: the flat version would record only the maximum requirement across all variables, losing per-variable precision.

Structural dataflow: x:₃A, y:₁B ⊢ (prev(x) + x + prev(prev(x))) * y : A Flat dataflow: x:A, y:B @³ ⊢ ... : A ^^ one scalar for whole context (loses that y needs only 1)

Liveness Analysis Structural

Each variable is annotated 0 (dead, not needed) or 1 (live, needed). Structural liveness tracks exactly which variables are live; flat liveness would only track whether any variable is live. Coeffect algebra: ({0,1}, max, min, 0, 1) — a Boolean semiring.

B Structural vs. Flat: The Formal Distinction

The distinction originates in Petricek–Orchard–Mycroft 2013 (ICALP) and is fully formalized in their 2014 ICFP paper. The key variable is the shape of the coeffect annotation vector.

x₁:τ₁, …, xₙ:τₙ @ʳ ⊢ e : τ

the entire context.

r ∈ R (a semilattice).

x₁:τ₁, …, xₙ:τₙ @⟨r₁,…,rₙ⟩ ⊢ e : τ

Core quote (Petricek, tomasp.net/coeffects, 2014): "The previously introduced notion of coeffects captured whole-context properties, but it failed to capture fine-grained per-variable properties. Context can capture additional properties of variables — usage patterns in linear logics; caching requirements in dataflow languages — as well as additional resources or properties of the execution environment."

Formal Shape Parameterization

The unified framework introduces a coeffect shape parameter S that determines the structure of the annotation vector:

Shape S = scalar → flat system: Γ @ₛ ⊢ e : τ (one element of S) Shape S = vector → structural: Γ @⟨s⟩ ⊢ e : τ (|Γ| elements of S) Flat instance: S = semilattice (R, ⊔, ⊥) Structural instance: S = semiring (R, +, ·, 0, 1)

The semiring structure is essential to structural systems: multiplication (·) scales the entire context when checking the body of an abstraction, while addition (+) merges contexts at application (cf. the linear logic ⊗/⅋ split). Flat systems need only a semilattice (join for combining, no multiplication).

Typing Rules Showing the Difference

Variable rule — structural system
(no premisses) 0·Γ, x :₁ A ⊢ x : AVar
All other variables get grade 0 (erased).
x gets grade 1 (used once).
Application — structural system (context addition)
Γ ⊢ e₁ : A →ˢ B     Δ ⊢ e₂ : A Γ + Δ ⊢ e₁ e₂ : BApp

+ is pointwise semiring addition on context vectors: (x :ᵣ A, Γ) + (x :ₛ A, Δ) = x :ᵣ₊ₛ A, (Γ+Δ)

Abstraction — structural system (grade peeled into function type)
Γ, x :ˢ A ⊢ e : B Γ ⊢ λx. e : A →ˢ BAbs

The grade s on x becomes the annotation on the function arrow →ˢ. In the flat system, s is instead merged into a single context annotation via ∧.

Scalar multiplication — structural system (graded modal promotion)
Γ ⊢ e : A r · Γ ⊢ !ᵣ e : !ᵣ A!-I

r · Γ multiplies every grade in Γ by r: r·(x :ₛ A, Δ) = x :ᵣ·ₛ A, (r·Δ). This is the !ᵣ promotion rule from Brunel et al. 2014.

Non-Structural Extension: Sharing Coeffects

Bianchini (building on Bianchini–Gaboardi) define a non-structural coeffect system for Java-like mutation and sharing: the coeffect of one variable can depend on another (transitive closure of sharing). Standard structural systems assume per-variable independence; sharing breaks this. Formally: the context is an ℛ-module rather than a simple vector space over the semiring.

ℛ-module context (non-structural sharing): Preorder: (x :ᶜ T, Γ) ⊆ (x :ᶜ' T, Δ) iff c' ⊆ c and Γ ⊆ Δ Sum: (x :ᶜ T, Γ) + (x :ᶜ' T, Δ) = x :ᶜ⁺ᶜ' T, (Γ+Δ) Scale: c × (x :ᶜ' T, Γ) = x :ᶜ×ᶜ' T, (c×Γ) -- Module law: (r+s)×u = (r×u)+(s×u); 0×u = 0; 1×u = u
C How Typing Contexts Are Annotated

Different lineages use different surface notation, but the underlying structure is always: each variable binding carries a grade (usage descriptor) from a semiring. The grammar of contexts is extended from the vanilla lambda-calculus context.

Two Main Lineages (from "Same Coeffect, Different Base", 2026)

Graded-Base Lineage QTT · Idris 2 · Linear Haskell
Δ ::= ∅ | Δ, x :ᵣ A

Every assumption graded.
No separate "linear" vars.
Judgment: Δ ⊢ᵍ t : A
Linear-Base Lineage Granule · Graded LL
Γ ::= ∅ | Γ, x:A | Γ, x:[A]ᵣ

Linear vars (bare) +
graded vars (in box).
Judgment: Γ ⊢ₗ t : A

Context operations are defined the same way in both lineages: addition is pointwise grade addition (disjoint on linear vars), scalar multiplication scales all grades.

Grammar Change: from λ-calculus to Structural Coeffect Calculus

Standard typing context: Γ ::= ∅ | Γ, x : A Structural coeffect context (graded-base): Γ ::= ∅ | Γ, x :ᵣ A (r ∈ R, a semiring) Structural coeffect context (linear-base): Γ ::= ∅ | Γ, x : A (linear assumption) | Γ, x : [A]ᵣ (graded assumption, r uses) Context addition (pointwise): (Γ, x :ᵣ A) + (Δ, x :ₛ A) = (Γ+Δ), x :ᵣ₊ₛ A (Γ, x :ᵣ A) + Δ = (Γ+Δ), x :ᵣ A (if x ∉ Δ) Scalar multiplication: r · (Γ, x :ₛ A) = (r·Γ), x :ᵣ·ₛ A Zero context (all-erased): 0·Γ = x₁ :₀ A₁, …, xₙ :₀ Aₙ -- all grades 0
Key structural invariant: In any well-typed structural system, contraction (Γ, x:A, x:A ⊢ e) is replaced by grade addition (Γ, x :₂ A ⊢ e), and weakening (Γ, x:A ⊢ e when x unused) becomes grade 0 (Γ, x :₀ A ⊢ e). The structural rules of the sequent calculus dissolve into semiring arithmetic.
Sources Annotated Bibliography
Coeffects: Unified Static Analysis of Context-Dependence
Tomáš Petříček, Dominic Orchard, Alan Mycroft
ICALP 2013

First paper to formally name and distinguish flat vs structural coeffects. Introduces the term "coeffect" and shows liveness analysis, linear types, and dataflow as instances. Demonstrates that flat systems (one annotation per context) fail to capture per-variable precision; structural systems (a vector) do. Shows that structural systems require a semiring (not just semilattice) because scaling the context requires multiplication.

Flat: Γ @ʳ ⊢ e : τ (r annotates the whole Γ) Structural: Γ @⟨r₁,…,rₙ⟩ ⊢ e : τ (rᵢ annotates each xᵢ)

Coeffects: A Calculus of Context-Dependent Computation
Tomáš Petříček, Dominic Orchard, Alan Mycroft
ICFP 2014 · ACM SIGPLAN Notices 49(9)

Full development of the unified structural/flat framework with indexed comonad semantics. Defines the shape-indexed annotation system; proves subject reduction and type soundness. Gives a complete categorical semantics via indexed comonads. The structural coeffect calculus has typing rules where Abs peels the bound variable's grade into the function-type annotation, App merges via pointwise addition.

Abs (structural): Γ, x :ˢ A ⊢ e : B → Γ ⊢ λx.e : A →ˢ B App (structural): Γ ⊢ f : A →ˢ B Δ ⊢ a : A → Γ + Δ ⊢ f a : B ↑ pointwise grade addition

A Core Quantitative Coeffect Calculus
Aloïs Brunel, Marco Gaboardi, Damiano Mazza, Steve Zdancewic
ESOP 2014 · LNCS 8410, pp. 351–370

Introduces ℝPCF: PCF extended with a semiring-annotated exponential modality !ᵣA. The context itself is standard (no per-variable grades directly); instead, per-variable quantitative information is mediated through the annotated bang: !ᵣA means "A used r times." Contraction on !ᵣA requires matching r; promotion scales the context by r. Connects directly to linear logic: !A = !ωA. This is a linear-base structural approach.

!-I: r·Γ ⊢ e : A → Γ ⊢ !ᵣe : !ᵣA !-E: Γ ⊢ e : !ᵣA Δ, x:ᵣA ⊢ e' : B → Γ+Δ ⊢ let !x = e in e' : B Contr: Γ, x:!ᵣA, y:!ᵣA ⊢ e : B → Γ, z:!ᵣA ⊢ e[z/x,z/y] : B (same r)

Combining Effects and Coeffects via Grading
Marco Gaboardi, Shin-ya Katsumata, Dominic Orchard, Flavien Breuvart, Tarmo Uustalu
ICFP 2016 · ACM SIGPLAN Notices 51(9), pp. 476–489

Unifies effects (what a computation does to context) with coeffects (what it demands from context) via grading. Effects form a graded monad; coeffects form a graded comonad. The combined type A →_{r,e} B carries both a coeffect grade r (resource demand) and an effect grade e (output change). Per-variable coeffect annotation: each variable in Γ carries a grade from a semiring. Subject reduction proven for the combined system.

Judgment: Γ ⊢_{e} e : A where Γ = x₁:ᵣ¹A₁, …, xₙ:ʳⁿAₙ (coeffects) e ∈ M (a monoid, effects) Linear function type: A →_{1,ε} B (use A once, no effect)
Structural PDF ACM DL ICFP 2016
I Got Plenty o' Nuttin'
Conor McBride
A List of Successes That Can Change the World (Wadler Festschrift) · LNCS 9600, pp. 207–233 · Springer 2016

Introduces per-variable usage annotations via a "rig" (semiring without subtraction) for dependent type theory. Each variable x in context carries a rig element ρ, written x :ᵨ A, encoding how many times x appears in a term. The key novelty: combines this with dependent types without collapsing linearity into the type index — the type of the output can refer to the input as a value even when x is linear (used once). This is the direct precursor to Atkey's QTT.

Context: x₁ :ᵨ¹ A₁, …, xₙ :ᵨⁿ Aₙ ρ = 0 → x is irrelevant (erased); may appear in types but not terms ρ = 1 → x is linear (used exactly once in the term) ρ = ω → x is unrestricted (may be used any number of times)
Structural PDF Springer Strathclyde
Syntax and Semantics of Quantitative Type Theory (QTT)
Robert Atkey
LICS 2018 · ACM/IEEE LICS proceedings

Full dependent type theory with per-variable semiring usage quantities. Judgment: x₁^ρ₁: S₁, …, xₙ^ρₙ: Sₙ ⊢ M^σ: T. The output annotation σ ∈ {0,1}: 0 = type-checking/erased, 1 = runtime use. Each ρᵢ ∈ R (quantitative semiring satisfying 0≠1, positivity, zero-product). 0-grade means the variable appears only in types (not erasure of computation but of operational relevance). Weakening is free at 0; contraction requires grade addition.

Var: (Γ + 0·Δ), x:₁A, 0·Θ ⊢ x^1 : A ^^^^^^^^^^ ^^ all-zero ↑ output σ=1 Scale: r·(x₁^ρ₁:A₁,…,xₙ^ρₙ:Aₙ) = x₁^(r·ρ₁):A₁,…,xₙ^(r·ρₙ):Aₙ

Quantitative Program Reasoning with Graded Modal Types (Granule)
Dominic Orchard, Vilem-Benjamin Liepelt, Harley Eades III
ICFP 2019 · PACMPL 3(ICFP)

Working implementation of structural per-variable graded coeffects in a functional language. Functions are linear by default (no contraction or weakening without explicit grade). Graded modal type !ᵣA (written A [r]) allows r uses of A. Semiring operations appear in grade expressions: twice : (a [c] → b) [2] → a [2*c] → (b,b). Supports abstract semiring parameters (coeffect polymorphism). Implements sensitivity analysis, information-flow control, and resource bounding as grade instantiations.

Type: a [n] -- type a, used exactly n times (grade n ∈ R) Unbox: [x] -- pattern match discharging the modal type Example: dup : forall {a : Type} . a [2] -> (a, a) -- attempts a -> (a,a) give linearity error

Coeffects for Sharing and Mutation
Riccardo Bianchini, Francesco Dagnino, Paola Giannini, Elena Zucca (and Marco Gaboardi)
arXiv 2022 (ESOP lineage)

Extends structural coeffects to non-structural sharing in Java-like languages. Standard structural systems compute each variable's coeffect independently. Shared object references violate this: variable x and y may alias, so x's coeffect depends on y's. Introduces ℛ-module contexts to model this dependency. Defines structural coeffects (pointwise independence) precisely as the special case where no two variables share coeffects.

Standard structural (independent): Γ = x₁ :_{c₁} T₁, …, xₙ :_{cₙ} Tₙ Non-structural (sharing, ℛ-module): x :_c T, Γ where c may depend on aliases in Γ Explicit definition of "structural": each variable's coeffect computed independently.

Same Coeffect, Different Base: Connecting Two Dominant Approaches to Graded Types
Orchard et al.
arXiv 2606.28042 · 2026

Establishes translations between graded-base and linear-base lineages, proving them type-, grade-, and semantics-preserving. Graded-base (QTT, Idris 2, Linear Haskell): grades pervasive on all assumptions. Linear-base (Granule, graded linear logic): linear assumptions plus graded modal types. The two differ in how linearity is encoded but are provably inter-translatable. Gives the cleanest formalization of the two context grammars.

Graded-base: Δ ::= ∅ | Δ, x:ᵣA Linear-base: Γ ::= ∅ | Γ, x:A | Γ, x:[A]ᵣ Addition (linear-base): (Γ, x:[A]ᵣ) + (Δ, x:[A]ₛ) = (Γ+Δ), x:[A]ᵣ₊ₛ Scale: r · (Γ, x:[A]ₛ) = (r·Γ), x:[A]ᵣ·ₛ Linear types: semiring {0,1,ω} with 1+1=ω, 0⊑ω, 1⊑ω

Modelling Coeffects in the Relational Semantics of Linear Logic
Breuvart, Pagani
CSL 2015 · LIPIcs

Shows coeffect systems are models of the !-exponential fragment of Linear Logic. Linear Logic's !A exponential already embodies structural per-variable resource tracking: contraction and weakening are explicit proof rules that are unsound without !. The relational semantics interprets ! as a multiset functor, whose weights correspond precisely to semiring grades.
